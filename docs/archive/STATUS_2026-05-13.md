## 3. Teacher audit — machinery green, K decision deferred

The `scripts/audit_teacher_topk_mass.py` script + `scripts/run_teacher_audit.sh` runner:
- Loads each teacher in bf16 with HuggingFace transformers `device_map="auto"` (tensor-parallel across visible GPUs)
- Computes per-position softmax top-K mass for K ∈ {4, 8, 16, 32}
- Aggregates median + p10 / p50 / p90 / p99 + frac_below thresholds
- Applies reviewer rule: "K=16 if any teacher's K=8 frac_below_0.95 > 0.10; else K=8"
- 14 unit tests cover the math (uniform / one-hot / monotone-in-K / explicit-sort agreement / threshold-escalation)

**Today's run validated the pipeline end-to-end** on OLMo-2-13B + DeepSeek-V2-Lite. The K=32 recommendation it produced is **not real**: the audit corpus was random uint32 token IDs in [0, 50000), which is uniform noise. Teachers facing noise produce near-uniform softmax (high entropy, low top-K mass) — so K=32 is a methodology artifact.

A future re-run on **real text** (each teacher's own tokenizer) will give a meaningful K decision. Not blocking Stage 1 (CE-only pilot); blocking Stage 3 (distillation cache budget).

## 4. The CUDA / pip dependency saga — what we learned

7+ failed install attempts on the H200 pod taught us the canonical single-venv recipe for JAX + PyTorch coexistence:

```
torch==2.7.1
jax[cuda12]==0.4.38
```

That works because torch 2.7.1's strict `==` nvidia-* pins (CUDA 12.6 ABI) satisfy JAX 0.4.38's loose `>=` pins. Single pip transaction, no `--force-reinstall`, no `--no-deps` workarounds. AXLearn (Apple's production JAX+PyTorch project) uses the same combo.

Failure modes catalogued in `requirements-gpu.txt` header — DO NOT:
- Use `--force-reinstall` on multi-package extras (corrupts the `nvidia/*` PEP 420 namespace)
- `pip install --upgrade nvidia-cudnn-cu12` (pulls 9.22.x → JAX `CUDNN_STATUS_NOT_INITIALIZED`)
- Install torch from `whl/cu124` (= torch 2.6 with stricter cuDNN 9.1 pin that fights everything)
- Forget to `unset LD_LIBRARY_PATH` (RunPod images pre-set it to shadow JAX's bundled cuDNN)

`pod_launch_gpu.sh` now does the right thing automatically. Future pods need 3 commands.

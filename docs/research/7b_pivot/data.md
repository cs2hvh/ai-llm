## RECOMMENDATION
Adopt the OLMo 3 / Dolma 3 recipe wholesale as your backbone rather than extending the legacy 13-source pipeline. It is the only 2025-26 recipe that is simultaneously competitive (OLMo-3 traded blows with Qwen3 at 7B/32B), fully downloadable (5.93T tokens, all ODC-BY — safe for a sovereign commercial model, unlike NVIDIA's Data-Agreement-licensed sets which need a legal read before redistribution), and fully documented through all four stages. Concretely: Stage 1 = Dolma 3 Mix proportions (~76% web / 14% science PDFs / 7% code / 3% math) at 5-6T tokens, with a 5-10% FineWeb-2 + HPLT-3.0 slice for your sovereign languages (your 131k tokenizer's main remaining advantage); Stage 2 = a Dolmino-style 100-150B mid-train that pushes code+math toward SmolLM3's ~37% end-state; Stage 2.5 = a dedicated agentic mid-train of 50-100B tokens built from daVinci-Dev's PR corpus plus Toucan-1.5M trajectories plus Nemotron-Pretraining-SFT-v1 — this stage is the single highest-leverage, lowest-cost addition for your agentic goal and did not exist publicly a year ago; Stage 3 = 50-100B long-context tokens (FinePDFs is purpose-built for this) with YaRN to 128K.

Kill the planned in-house Rust migration: Ai2 already shipped exactly that stack (duplodocus, datamap-rs, decon, Apache-2.0), and on your B200 fleet NeMo-Curator's GPU MinHash dedup is faster still. Keep the old corpus pipeline only as a thin ingestion layer for local-language sources absent from Common Crawl, run through datatrove/datamap-rs with the DCLM fastText and FineWeb-Edu classifiers, then globally dedup and decon-decontaminate everything together before each stage. Budget-wise, 6T tokens for a 7B is Chinchilla-excessive but matches OLMo 3 and is well within multi-cluster B200/B300 reach; do not chase Qwen3's 36T — data engineering, not compute, is your scarce resource as a solo lead, and every component above is a download rather than a build.

## 2. Code

- **The Stack v2 / StarCoder2Data** (Feb 2024): 67.5TB full / 32.1TB deduped; ~900B training tokens, 619+ languages, built on Software Heritage; StarCoder2 models trained 3.3–4.3T tokens. License: per-file source licenses + BigCode governance. [paper](https://arxiv.org/abs/2402.19173), [repo](https://github.com/bigcode-project/the-stack-v2) (2026-07-23).
- **Stack-Edu** (HF, 2025): 125B tokens of educational code filtered from StarCoder2Data via 15 language-specific StarEncoder classifiers (Llama3-70B synthetic labels, threshold 3/5); beats StarCoder2Data on MultiPL-E across all languages. This is the code component of both SmolLM and **OLMo 3** (409B tokens in Dolma 3 Mix, i.e. upsampled). [HF](https://huggingface.co/datasets/HuggingFaceTB/stack-edu).
- **OpenCoder / RefineCode** (Nov 2024): 960B tokens, 607 languages, 130+ language-specific filtering rules, +75B code-related web tokens; released as reproducible metadata rather than full text. [paper](https://arxiv.org/pdf/2411.04905), [HF meta](https://huggingface.co/datasets/OpenCoder-LLM/RefineCode-code-corpus-meta).
- **Nemotron-Pretraining-Code-v2** (Dec 2025): refreshed GitHub-sourced corpus + 427.9B tokens of CC-extracted code pages via the Lynx+LLM pipeline. NVIDIA Data Agreement. [HF](https://huggingface.co/datasets/nvidia/Nemotron-Pretraining-Code-v2).

## 3. Math

- **MegaMath** (LLM360, COLM 2025): 371B tokens (web re-extraction + Stack-v2 math code + 80B+ synthetic QA/code). Largest open math corpus. [paper](https://arxiv.org/abs/2504.02807), [HF](https://huggingface.co/datasets/LLM360/MegaMath).
- **FineMath** (HF): ~54B tokens total; FineMath-3+/4+ are the quality tiers. OLMo 3 uses FineMath-3plus (151B tokens in-mix, i.e. multiple epochs). [search context](https://huggingface.co/datasets/HuggingFaceTB/finemath) (referenced via SmolLM3/OLMo3 sources).
- **Nemotron-CC-Math** (Aug 2025): 133B tokens; Lynx+LLM pipeline preserving equations/LaTeX; claims 5.5x larger than FineMath-4+ and better downstream math/code. [arXiv 2508.15096](https://arxiv.org/pdf/2508.15096).
- OpenWebMath (~14.7B) is now effectively superseded by the above (UNVERIFIED size, from memory).

## 5. What proven 2025-26 recipes actually train on, per stage

**OLMo 3 (Ai2, Nov 20 2025; 7B and 32B)** — the only fully open end-to-end recipe at competitive quality, and the closest blueprint for this project ([Ai2 blog](https://allenai.org/blog/olmo3), [HF mix](https://huggingface.co/datasets/allenai/dolma3_mix-6T-1025-7B)):
- **Stage 1 pretrain, 5.93T tokens**: 76.07% Common Crawl web (4.51T), 13.57% olmOCR science PDFs (805B), 6.89% Stack-Edu code (409B), 2.56% FineMath-3+ (151B), 0.86% ArXiv/ProofPile (50.9B), 0.04% English Wikipedia. All ODC-BY.
- **Stage 2 mid-train ("Dolmino"), 100B tokens** sampled from a 2.2T pool of math, science, code, instruction-following, reading-comprehension and reasoning traces; mix chosen by "microannealing" ablations (5B target + 5B web anneals per candidate source).
- **Stage 3 long-context ("Longmino"), 50B tokens** (7B) from a 639B pool of long documents (heavy on olmOCR PDFs), with YaRN.
- Result: OLMo-3-Think-32B competitive with Qwen3-32B (e.g. MATH 96.1 vs 95.4 per Ai2's post).

**SmolLM3 (HF, July 2025, 3B, 11T tokens)** — cleanest public 3-stage ratio curriculum ([datasets collection](https://huggingface.co/collections/HuggingFaceTB/smollm3-pretraining-datasets-685a7353fdc01aecde51b1d9), [summary](https://learnopencv.com/smollm3-explained/)):
- Stage 1 (~8T): **85% web / 12% code / 3% math**
- Stage 2 (~2T): **75% web / 15% code / 10% math** (Stack-Edu, FineMath4+, MegaMath enter)
- Stage 3 (~1.1T, anneal): **63% web / 24% code / 13% math** — code+math upsampled at the end.

**Qwen3 (May 2025 tech report)**: 36T tokens, 119 languages; Stage 1 ~30T general at 4K context; Stage 2 ~5T knowledge-intensive (STEM/code/reasoning up-weighted); Stage 3 hundreds of billions of long-context tokens at 32K (75% of docs 16-32K). Instance-level mixture optimization via a multilingual annotation system over 30T tokens. [report](https://arxiv.org/pdf/2505.09388), [blog](https://qwenlm.github.io/blog/qwen3/).

**DCLM-7B (2024)**: 3.8T DCLM-baseline + StarCoder + ProofPile2 = 4.1T — evidence that a single well-filtered web corpus + code + math gets you a strong base. [paper](https://arxiv.org/html/2406.11794v1).

**Gemma 4 (Google, April 2 2026)**: five sizes (E2B, E4B, 12B, 26B-A4B MoE, 31B dense), 128K-256K context, data cutoff Jan 2025 — but the data recipe is closed, so it is a benchmark target, not a copyable recipe. [model card](https://ai.google.dev/gemma/docs/core/model_card_4), [tech report](https://arxiv.org/html/2607.02770v1).

**Pattern across all recipes**: web-dominant start → code/math/QA up-weighting in mid-training → short high-quality anneal with instruction-formatted and reasoning data → separate long-context extension stage. Nemotron additionally puts SFT-style data directly into pretraining (Nemotron-Pretraining-SFT-v1).

## 6. Quality filtering — reusable off-the-shelf (all proven at trillion-token scale)

1. **DCLM fastText classifier** (trained on OpenHermes-2.5 + r/ELI5): the single highest-value cheap filter per the DCLM ablations. [DCLM repo](https://github.com/mlfoundations/dclm).
2. **FineWeb-Edu classifier** (Llama3-70B-annotated, regression head): produced FineWeb-Edu (1.3T) and inspired Stack-Edu. [HF model](https://huggingface.co/HuggingFaceFW/fineweb-edu-classifier).
3. **NVIDIA ensemble** (Nemotron-CC): fastText + FineWeb-Mixtral-Edu + FineWeb-Nemotron-4-Edu classifiers, scores bucketed into 20 percentile bins, max-ensembled — all published: [nemocurator-fineweb-nemotron-4-edu-classifier](https://huggingface.co/nvidia/nemocurator-fineweb-nemotron-4-edu-classifier), [quality-classifier-deberta](https://huggingface.co/nvidia/quality-classifier-deberta), method in [NVIDIA blog](https://developer.nvidia.com/blog/building-nemotron-cc-a-high-quality-trillion-token-dataset-for-llm-pretraining-from-common-crawl-using-nvidia-nemo-curator/).

Note: with Dolma 3 / Nemotron / FineWeb-family data you inherit the filtering already done; you only need classifiers for your own sovereign-language crawl additions.

## 7. Dedup + decontamination best practice (2026) and tooling

- **Fuzzy dedup**: MinHash + LSH remains standard. NeMo-Curator defaults: 128 hashes, Jaccard threshold ~0.8, GPU-accelerated (cuDF/RAPIDS), trillion-token scale in hours on one 8-GPU node — ideal given your B200/B300 fleet ([NeMo-Curator docs](https://docs.nvidia.com/nemo/curator/25.09/curate-text/process-data/deduplication/index.html), [repo](https://github.com/NVIDIA-NeMo/Curator)). FineWeb used 5-gram MinHash with 112 hash functions (14 buckets x 8) ~0.75 threshold ([FineWeb paper](https://arxiv.org/pdf/2406.17557)).
- **Ai2's new Rust stack (shipped with OLMo 3)**: **duplodocus** (exact + MinHash fuzzy dedup at trillion-token scale, memory/disk modes) [GitHub](https://github.com/allenai/duplodocus); **datamap-rs** (pure-Rust large-scale cleaning/filtering) [GitHub](https://github.com/allenai/datamap-rs/); **decon** (n-gram benchmark decontamination / test-set removal) — named in the [Ai2 OLMo 3 blog](https://allenai.org/blog/olmo3). OLMo 3 also introduced global (cross-source) dedup at trillion-token scale, which materially reduced benchmark contamination.
- **Decontamination**: n-gram overlap removal against your full eval suite before every stage (pretrain, mid-train, anneal), using decon or datatrove's decontamination blocks; Dolma 3 Mix's "much stronger decontamination" is called out as a headline feature.
- **datatrove** (HF, Python/Rust-accelerated) built FineWeb/FinePDFs and remains the best-documented CPU pipeline. [FinePDFs used it](https://huggingface.co/datasets/HuggingFaceFW/finepdfs).

**Verdict on the legacy 13-source multilingual pipeline + planned Rust migration**: do NOT carry it as the backbone and do NOT write your own Rust tooling. FineWeb-2 (1,893 language-script pairs, ODC-By) and HPLT 3.0 (30T tokens, ~200 languages, CC-BY, full open pipeline) now cover multilingual web better than any solo-maintained crawler. The only part worth keeping is a thin ingestion layer for truly sovereign sources (local-language documents not in CC), processed with datamap-rs/datatrove + duplodocus — i.e. the Rust migration is already done for you by Ai2.

## 8. Agentic goal: code share + agentic mid-training data

- **Code share evidence**: Aryabumi et al., "To Code, or Not To Code" ([arXiv 2408.10914](https://arxiv.org/pdf/2408.10914)) — ~25% code in the corpus is the best-overall point; code yields up to 8.2% relative improvement on NL reasoning; >75% code collapses knowledge tasks. Code pretraining also improves entity tracking ([arXiv 2405.21068](https://arxiv.org/pdf/2405.21068)) and cross-domain reasoning ([arXiv 2509.21499](https://arxiv.org/pdf/2509.21499)). SmolLM3's final-stage 24% code and OLMo 3's code-heavy Dolmino confirm the practice.
- **Agentic mid-training is now an established, named stage** ([survey/topic](https://www.emergentmind.com/topics/agentic-mid-training)): next-token training on instruction/trajectory-formatted data between pretraining and SFT/RL.
- **Public datasets that exist today**:
  - **daVinci-Dev** (SII-GAIR, Jan 2026): 68.6B-token "contextually-native" corpus reconstructed from ~4.1M GitHub PRs (+3.1B tokens of execution-grounded trajectories); mid-training on 73.1B tokens took non-coder Qwen2.5-Base to 56.1% (32B) / 58.5% (72B) on SWE-Bench Verified. ~60% of the PR corpus is released at [HF GAIR/daVinci-Dev](https://huggingface.co/datasets/GAIR/daVinci-Dev), [arXiv 2601.18418](https://arxiv.org/abs/2601.18418). This is the single most relevant public artifact for your agentic goal.
  - **Toucan-1.5M** (IBM/UW, Oct 2025): 1.5M tool-agentic trajectories from 495 real MCP servers / 2,000+ tools, with real executions, multi-turn and parallel calls; fine-tuned models beat larger closed models on BFCL-V3. [HF](https://huggingface.co/datasets/Agent-Ark/Toucan-1.5M), [arXiv 2510.01179](https://arxiv.org/abs/2510.01179).
  - **Nemotron-Pretraining-SFT-v1** (NVIDIA): instruction/SFT-style data designed for the pretraining phase. [HF](https://huggingface.co/datasets/nvidia/Nemotron-Pretraining-SFT-v1).
  - **Agentic CPT / AgentFounder** (Alibaba Tongyi, [arXiv 2509.13310](https://arxiv.org/abs/2509.13310)): method fully described (first-order action synthesis, offline tool-sim), model AgentFounder-30B hits 39.9% BrowseComp-en; the synthesis recipe is reproducible but the data itself is not released — treat as a recipe to replicate with Toucan/MCP environments.
  - Nemotron 3 Nano (Dec 2025) is explicitly an "agentic reasoning" model whose pretraining corpora are the open Nemotron v2/v2.1 sets — evidence this data stack supports agentic targets. [arXiv 2512.20848](https://arxiv.org/pdf/2512.20848).

## 9. Bottom line per stage for a 2026 7B agentic model

- **Stage 1 (~5-6T tokens)**: clone Dolma 3 Mix proportions (76% filtered web, ~14% PDFs/science, ~7% code, ~3% math), substituting/augmenting web with Nemotron-CC-v2 high-quality buckets and adding a 5-10% FineWeb-2/HPLT-3.0 slice for your sovereign languages (your 131k SPM tokenizer already supports them).
- **Stage 2 mid-train (~100-150B)**: Dolmino-style — math (MegaMath/Nemotron-CC-Math), Stack-Edu code, QA, instruction (Tulu-3-style), reasoning traces; push combined code+math toward SmolLM3's 24%+13% end-state.
- **Stage 2.5 agentic mid-train (~50-100B)**: daVinci-Dev PR corpus + Toucan-1.5M formatted trajectories + Nemotron-Pretraining-SFT — this stage is the differentiator for the agentic goal and did not exist publicly a year ago.
- **Stage 3 long-context (~50-100B)**: FinePDFs + long code repos, YaRN, to 128K+.
- Tooling: NeMo-Curator (GPU dedup on B200) + Ai2 Rust stack (duplodocus/datamap-rs/decon) + datatrove; decontaminate every stage against your eval suite.

## OPEN QUESTIONS
- Exact license terms and redistribution constraints of the NVIDIA Data Agreement for Model Training (Nemotron-CC-v2/v2.1) for a commercial 'sovereign' model — needs legal review; unclear whether trained-model indemnity or data-redistribution limits conflict with the project's sovereignty claims.
- FineMath-3+ is ~34-54B unique tokens but appears as 151B tokens in the Dolma 3 Mix — the implied upsampling/epoch policy per source is not documented on the dataset card; the OLMo 3 paper needs a close read to replicate per-source epoch counts.
- The Ai2 dataset card notes olmOCR science-PDF documents contain '[REMOVED]' redactions, so bit-exact reproduction of OLMo 3 is impossible — how much the redacted fraction matters at 805B-token scale is unknown.
- No public ablation exists on the optimal token budget or placement of agentic trajectory data (daVinci-Dev/Toucan-style) — whether small amounts belong in Stage 1 pretraining vs concentrated in mid-training is unresolved; daVinci-Dev only tests mid-training on Qwen2.5 bases.
- Toucan-1.5M's exact license was not verified live (reported permissive/Apache-style via IBM, UNVERIFIED); also ~40% of daVinci-Dev's PR corpus is withheld.
- How OLMo 3's token counts translate under the project's own 131k SPM-Unigram tokenizer (token counts shift 5-15% across tokenizers), affecting mix percentages and compute budgeting.
- Gemma 4 (April 2026) and Qwen3 data recipes remain closed beyond coarse stage descriptions, so competitive parity claims can only be validated by benchmark, not by data-side comparison.
- Whether OLMo 3's 32B used the identical 5.9T mix or a larger 6.5T+ variant was not conclusively verified live (the 7B card documents 5.93T).

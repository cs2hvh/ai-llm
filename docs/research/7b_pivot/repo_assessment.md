# Salvage Inventory — MyLLM (1B JAX/Keras) → 7B Agentic Model Pivot

**Assessed repo:** `D:\work\ai-llm` @ `00a825f` (main, clean). ~39K LOC total: `src/myllm` 11.4K, `scripts` 10K, `tests` 14.7K, plus docs/configs. Suite last known green at 739 passed / 1 skipped.

**Single most important structural fact:** the codebase is cleanly stratified by framework coupling. Only 14 files import JAX/Keras/Optax/Orbax (`model/`, most of `training/`, `infer/predict.py`, `utils/determinism.py`). The entire data pipeline (`src/myllm/data/`, 4,916 LOC), the eval layer (`PredictFn` abstraction), `watchdog.py`, `quarantine.py`, `schedule.py`, `decay_phase.py`, `runpod_orch/`, and `utils/storage.py` are **pure Python with zero framework imports**. This makes the PyTorch scenario far cheaper than a typical stack pivot.

**Second structural fact:** the pivot's hardware premise (company-owned B200/B300 clusters) invalidates two load-bearing assumptions of the old plan — "no cluster, one 128-core node" (basis of the Rust migration plan) and "burst-rent RunPod pods" (basis of the orchestration module). Both need re-decision, not porting.

## 2. Component notes (the "why" behind non-obvious verdicts)

- **Tokenizer:** SentencePiece artifacts are framework-neutral (HF `tokenizers` loads them; the JSON is already on R2). Critically, `special_tokens.py` already reserves `<|im_start|>`, `<|im_end|>`, `<|tool_call|>`, `<|tool_result|>` — the agentic pivot was partially anticipated. Caveats for 7B: 131k vocab is in the modern range (Qwen3 ~151k BPE, Gemma 262k SPM), but the vocab was fit to a 44%-fineweb 13-source mix; a "lite coding" model wants a retrain on a more code-heavy corpus (audit digit-splitting and whitespace handling for code). The *pipeline* (train + validation harness + constants discipline) is the salvage; the v2 artifact is usable for bring-up.
- **Data pipeline:** the crown jewel. Provenance schemas (`DocSpan`, `SequenceMeta`, `CorpusManifest`), deficit-driven compose with a measured ≤0.33pp mix drift, dual 8/13-gram decontamination with audit-trail CSVs, quarantine-compatible `seq_meta.arrow` position mapping — none of this cares what consumes the tokens. A PyTorch `IterableDataset` over `tokens.bin` + packed frames is 2–5 days. The real work is throughput: the pipeline is single-thread Python (92 seq/s compose, measured), sized for 5B tokens; a 7B model wants 5–15T. That gap should now be closed with cluster-scale curation (see #12), not the Rust plan.
- **Teacher cache:** Arrow top-K format (bf16 logits + uint32 indices, 48 B/token/teacher) plus atomic manifest I/O is framework-free and spec-documented (`docs/teacher_logit_cache_format.md`). The *strategy* doc must be redone: student is now 7B (KD calculus changes — teachers must be much larger or distillation dropped for later stages), token budgets 10–100× larger, and cross-tokenizer KD remains the unresolved caveat flagged in §7 of the handoff.
- **Training loop policies vs. code:** the durable value is the *reliability envelope* — atomic NaN-revert with step-always-advances semantics, Welford 6σ watchdog with tested `_recover_from_spike` (restore ckpt → halve LR → skip ahead), quarantine JSONL with enough provenance to decode the poisonous document, per-source val-loss bucketing. All of that expresses naturally as torchtitan callbacks/hooks, and the detector + writer modules literally import as-is.
- **Eval:** the runner/scorecard skeleton is backend-agnostic (`PredictFn` boundary was built for exactly this). But be honest about coverage: IFEval/HumanEval+/MBPP+ scoring is still placeholder (D6 partial), and an agentic 7B needs an entirely different tier of evals (function-calling, multi-turn tool use, agent trajectories). Expect to adopt lm-eval-harness + agentic harnesses and keep this layer as the scorecard/gating wrapper.
- **Rust plan:** locked but zero code exists — sunk cost is only the planning. Its research is still worth money (see IP list), but at cluster scale prefer the industry path the plan itself cataloged (Dolma's Rust dedup as a library, DCLM BFF, DCLM/FineWeb-Edu classifiers) run distributed, or GPU curation.

## 3. Hard-won IP that must not be lost (stack-independent)

Carry these forward verbatim into the new repo's docs, whatever the stack:

1. **`docs/SESSION_HANDOFF.md` §3 gotchas list (10 items).** Several are JAX-flavored but map to general classes: int32 data-cursor overflow inside compiled step state (~step 65.5K); "single-pass iterators that look infinite" (multi-epoch flag mandatory); exact version pinning with API-compat smoke tests (`tests/test_orbax_api_compat.py` pattern — replicate for torch/DCP); buffer-donation invalidating state for later callers; prose drift between "what ran" and "what docs claim" (DP vs FSDP).
2. **The bf16 large-vocab CE lesson (D8).** Finite forward loss + NaN gradients at V=131k/bf16/scale, fixed by fp32 logsumexp accumulators, with a full audit doc (`docs/design/d8_chunked_ce_audit.md`). In PyTorch this argues for Liger/Cut-Cross-Entropy fused kernels (the D11 item is solved off-the-shelf there) — but the *failure signature and diagnosis method* is the transferable asset.
3. **D9 + D13 data lesson.** A single Stack Exchange doc spanning a full 8K sequence deterministically NaN'd gradients (step 718, reproducible across 3 runs); root-caused via quarantine JSONL → `seq_meta.arrow` mapping (`scripts/inspect_quarantine.py`). Conclusion: Gopher repetition filters + byte-entropy floors belong in the corpus pipeline. At 5–15T tokens this class of bug is guaranteed to recur — the forensic tooling and the filter recommendation must ship day one.
4. **Muon empirical result (2026-05-20, 2×B200).** Muon with muP `1/width_mult` scaling on hidden matrices descends at only ~63% of AdamW's rate; disabling the scaling (`muon_disable_mup_scale=true`) fully matches AdamW by 500 steps — empirically validating that Muon's spectral-norm bound makes muP scaling redundant for hidden matrices. Directly relevant to a 7B Muon run in any framework. Also: MuonClip threshold/alpha values and the "only one production deployment" caveat.
5. **Decontamination indexes + builder.** 8/13-gram xxhash64 indexes over 11 benchmarks (~75 MB, on R2) + `scripts/build_decontamination_index.py`. Reusable immediately; extend the benchmark set with the agentic eval suite *before* the first 7B corpus build — decontamination is retroactively impossible.
6. **Teacher/license legal vetting (`teacher_distillation_strategy.md` + `license_register.md`).** The Mistral "Modified MIT" $20M-revenue clause catch, Gemma TOS §3.2 ("Model Derivatives" includes synthetic outputs), Llama 700M-MAU clause, OpenAI/Anthropic output-use prohibitions, and the base-vs-instruct/multimodal teacher screen. This vetting applies unchanged to any 7B distillation or synthetic-data decision and took real review cycles to accumulate.
7. **Governance artifacts + the verify-before-locking discipline.** The EU AI Act/ISO 42001/NIST/DPDP card scaffolding with auto-rendered blocks and a CI staleness gate, and the documented practice of WebFetch-verifying every external claim before config locks (which caught the Gemma 3 softcap→QK-norm change and the stale-reviewer claims). For a from-scratch 7B intended for release, this is months of compliance lead time already banked.
8. **Rust-plan research ledger.** rensa's non-xxh64 hasher silently invalidating indexes; DCLM issue #71 (98% data loss from default BFF params — tune on 5–20B first); FineWeb-Edu classifier is a transformer, not fastText (community fastText port is a 32%-accuracy regression); Dolma-as-a-library exposes AI2's Rust dedup; suffix-array dedup RAM math. All directly applicable to the 7B corpus build regardless of execution substrate.
9. **Methodology artifacts:** per-source PPL/val-loss bucketing (with banked pilot baselines for sanity-checking the new stack's data path), the mix-drift ledger, WSD decay-to-zero adoption (Bergsma), QK-norm-replaces-attn-softcap + final-softcap=30 verification trail, and the wind-tunnel/muP sweep *protocol* (proxy models → LR-transfer sweep at target shape) — the protocol is exactly what de-risks 7B hyperparameters, even though the 1B numbers don't transfer.

## 4. What is 1B-specific and dies with the pivot

- **All locked hyperparameters and configs:** `base_1b.yaml` (2048/8192, GQA 4:1), `pilot_250m*.yaml`, `wind_tunnel*.yaml`, peak_lr=3e-4, mb=4, seq=4096, 20B-token Stage 2 contract. The muP *transfer claim* (250M→1B confirmed) validates the method, not any 7B config — a fresh sweep at 7B shape (and likely deeper-thinner per D12) is mandatory.
- **C2/C3 throughput benchmarks and cost models** (MFU tables, $/token math, hardware pivot history) — shape-, framework-, and rental-price-specific.
- **~85 GB of checkpoints** (pilot 250M final, 6 muP-sweep 1B checkpoints) — archive for forensics; no forward training value. Same for the Stage-2 launch runbooks.
- **The 5B-token pilot corpus** — three orders of magnitude too small for 7B, and the 44%-web mix is wrong for an agentic/coding target anyway (needs much heavier code, math, and eventually tool-trace/instruction data). The *pipeline* survives; this *corpus* doesn't.
- **Scenario (a) only:** all 14 JAX-coupled files (Keras 3 model, JIT train/eval steps, mesh/sharding, Orbax checkpoint + reshard code, optax Muon wiring, chunked-CE implementation), plus their tests (~half the suite). The D8 chunked-CE bug is a JAX/XLA artifact — in torch-land the problem class is pre-solved by fused CE kernels.
- **Likely dead in both scenarios:** RunPod orchestration (owned clusters), the Rust migration plan as written (cluster invalidates the single-node premise), and the teacher cost/storage math sized for a 150B-token 1B decay phase.
- **Partially dying:** teacher selection itself — DeepSeek-V4-Pro-Base + Olmo-3-32B were chosen as teachers for a 1B student; a 7B student narrows the useful teacher gap and shifts the KD-vs-more-tokens tradeoff. The *vetting framework* survives (item 6 above); the picked set needs re-derivation.

## 5. Bottom line

- **Scenario (a) — PyTorch/torchtitan (likely):** salvage ~60% of the repo's value. Reuse wholesale: data pipeline, tokenizer pipeline + artifact, teacher-cache format, watchdog/quarantine, eval skeleton, governance, R2 tooling, and the entire gotcha/IP ledger (~95–150 person-days). Deliberately drop the JAX 40% and inherit torchtitan's model/loop/checkpoint — this trades salvage for a proven-at-scale 7B substrate, which matches the owner's "proven, not experimental" mandate.
- **Scenario (b) — stay JAX at 7B:** salvages more code (~145–230 days) but the retained pieces are exactly the least-proven at 7B: Keras 3 layers were never run above 1B, D7 sharding rules are unbuilt, and the D8 bug class lurks at larger vocab/scale. A realistic JAX path migrates to MaxText anyway, which claws back much of the difference — so the framework decision should be driven by ecosystem (agentic post-training, RL, inference tooling are strongest in PyTorch), not by salvage economics.
- Regardless of stack, before writing any new code: freeze and export the IP list in §3 (especially the gotchas file, decontamination assets, license register, and Muon/muP findings) into the new project's founding docs, and keep the R2 bucket layout — it is the one substrate both scenarios share.
